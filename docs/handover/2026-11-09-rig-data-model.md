## ここまでで決まったこと

- 用語は仕様書 1.3、作り直し中のデータの形は仕様書 2.0 にある。まずこの2つを読む
- 大きな方針
  - リグは「ピース（ライン・パーツ・接続）」の組み合わせで、枝分かれのある形。一直線の配列ではない（仕様書 2.1〜2.4 は古い形のまま。2.0 が固まったら置き換える）
  - 向きは「上・下」ではなく、力の向き（タックル側・先側・重力・荷重）で考える。輪はない
  - ラインもパーツもポイントを持つ。ラインのポイントは始まりからの距離で、幅を持てる。ラインは途中で分けない
  - 接続は 結束・連結・通し の3種類。ポイントの幅の意味は接続の種類で決まる
  - 「項目は、それを使う計算か画面ができるときに足す」。細かい物理の項目は「将来の候補」に置いている
- 竿・道糸側は「タックル」、タックル＋リグの組み合わせは「セットアップ」（仕様書 1.3・2.5）

### 仕掛けの中身

上（タックル側）から：

- サルカン（環が2つ。タックル側の環に道糸・リーダーを結ぶ）

### 計算の確かめ

| 値 | 計算 | 結果 |

| 全長 | タックル側の端 → いちばん遠い先端（オモリ）：幹糸 110 ＋ 捨て糸 50 ＋ オモリ 5 | 165cm |

### 重さの見立て

- ピース 8個、接続 7個。単純な仕掛けでも数は多い
- ただし、たくみが1つずつ入れるわけではない。エディタで「枝スを追加」を押すと、枝ス・針・エダス結び・外掛け結びの4つをまとめて作る、のような作りにすれば、入力の手間は今の「パーツの積み上げ」とほぼ同じ
- データが細かいのは、画面で隠せる。逆に、データが粗いと、あとで細かくできない

### 気になる点（相談したい）

1. **パーツのポイントに位置を持たせていない**。オモリだけ `length` を持たせた。サルカンの環と環の間の長さや、三又の3つの環の位置は、今は0扱い（仕様書の「金具の長さは入れなければ0」と同じ）。これで足りるか
2. **接続をピースとは別の配列（`joints`）にした**。仕様書 1.3 では接続も「ピースの1つ」だが、データでは「ほかのピースをつなぐもの」なので分けたほうが扱いやすい。考え方としてはピース、データの置き場所は別、でよいか
3. **タックル側の端を `tackleSide` で指した**（サルカンの環 a）。向き（タックル側・先側）は、ここからつながりをたどって決まる
4. **ラインの両端のポイントの id を `start`・`end` に固定した**。両端は必ずあって消せないので、決まった名前のほうが扱いやすいため
5. **枝スの `role` に `edasu` を足した**。今の仕様書の `role` には枝スがなく、ハリス `harisu` だけ。枝スとハリスを分けるか、まとめるか
6. **`type`（胴付き・天秤などの構成タイプ）を外した**。つながりから見て分かるので要らないかもしれない。一覧で絞り込むのに使うなら残す
7. **`layout` は空**。#3（エディタ）を作るときに、角度・色を足す
